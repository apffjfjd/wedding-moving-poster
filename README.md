# 셀프 웨딩 무빙 포스터

신랑·신부 사진을 올리면, 동영상 렌더링 없이 **브라우저에서 실시간으로** 전환·애니메이션 효과를 적용해
**URL 하나로 결혼식장에서 무한 반복 재생**하는 웨딩 슬라이드쇼 서비스. (설계: BD-0003 / 요구사항: REQ-0003)

두 가지 방식으로 쓸 수 있다.
**서버 모드**(직접 호스팅, 웹에서 업로드·편집)와 **Pages 모드**(GitHub Pages + 구글 드라이브, 서버 없음 → 아래 "모드 2").

## 실행 (서버 모드)

```bash
npm start                      # http://127.0.0.1:3000
PORT=8080 HOST=0.0.0.0 npm start   # 외부(현장 PC 등)에서 접속하려면 HOST 지정
npm test
```

- Node.js 20+ 필요, **외부 의존성 없음**.
- 데이터는 `DATA_DIR`(기본 `./data`)에 파일로 저장된다: `data/<id>/meta.json`, `data/<id>/photos/*`.

## 사용 흐름

1. `/` 에서 **슬라이드쇼 만들기** → 편집 화면(`/e/<id>#key=...`)으로 이동
2. 사진 업로드(여러 장, 끌어놓기 가능). 브라우저에서 긴 변 1920px JPEG로 축소해 올리므로 원본이 수 MB여도 가볍다.
3. 사진별 효과를 **자동** 또는 직접 선택. 오른쪽 미리보기에 즉시 반영된다.
4. **재생 URL**(`/s/<id>`)을 결혼식장 PC에서 열고 클릭 또는 `F` 키로 전체화면. 마지막 사진 뒤 처음으로 돌아가 무한 반복한다.

사진/효과를 바꾸면 재생 URL은 재렌더링 없이 열려 있는 화면에도 최대 10초 안에 반영된다.

## 모드 2: GitHub Pages + 구글 드라이브 (서버 없이 호스팅)

Pages는 정적 파일만 서빙하므로 서버 모드(위)는 올릴 수 없다. 대신 **드라이브 폴더를 편집기로** 쓴다.
폰/PC에서 폴더에 사진을 넣고 빼고 이름을 바꾸면, 재생 URL이 재배포 없이 약 30초 안에 따라온다.

```
구글 드라이브 폴더 ──(Drive API, 30초마다)──▶ https://<user>.github.io/<repo>/player.html?folder=<폴더ID>
```

### 사진과 효과 (파일명 규칙)

- 재생 순서 = **파일명 순서** (숫자는 크기순: `2`가 `10`보다 먼저). 이미지가 아닌 파일과 `.`으로 시작하는 파일은 무시한다.
- 파일명에 **효과 이름**을 `_` 또는 공백으로 이어 붙이면 그 사진에 적용된다. 없으면 자동.
  `01_kenburns.jpg` · `02_zoom-in.jpg`(하이픈·대소문자 무시) · `03.jpg`(자동) · `04_blur.jpg`
- 효과 이름: `fade` `crossdissolve` `zoomin` `zoomout` `pan` `kenburns` `blur` `parallax` `auto`
- 사진 방향·크기는 실제로 불러온 이미지에서 측정한다(EXIF 회전 반영). HEIC도 드라이브가 변환해 주는 이미지로 재생된다.

### 1회 설정

1. **드라이브 폴더 공유**: 폴더 → 공유 → 일반 액세스 "링크가 있는 모든 사용자", 역할 "뷰어". (예식 후 공유 해제 권장)
2. **Drive API 키 만들기** ([Google Cloud Console](https://console.cloud.google.com/))
   1. 프로젝트 생성 → *API 및 서비스 → 라이브러리* 에서 **Google Drive API** 사용 설정
   2. *사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키*
   3. 키 제한(**필수** — 키가 브라우저에 노출됨): 애플리케이션 제한 = *웹사이트*, 허용 주소 `https://<user>.github.io/*` (로컬 확인용으로 `http://localhost:*` 추가 가능) / API 제한 = *Google Drive API* 만
3. **키 넣기**: `pages/config.js` 의 `apiKey` 에 붙여넣거나, GitHub 저장소 *Settings → Secrets and variables → Actions → Variables* 에 `DRIVE_API_KEY` 로 등록
4. **배포**: 저장소를 GitHub에 올리고 *Settings → Pages → Source* 를 **GitHub Actions** 로 지정 → `main` push 시 `.github/workflows/pages.yml` 이 테스트·빌드·배포한다.
   (무료 Pages는 저장소가 public이어야 하지만, 저장소에는 **사진이 없다**. 사진은 드라이브에만 있다.)
5. `https://<user>.github.io/<repo>/` 에서 폴더 링크를 붙여넣어 재생 URL을 만든다.

로컬에서 빌드만 확인하려면 `npm run build:pages` 후 `dist/` 를 아무 정적 서버로 열면 된다.

### 사진 불러오기 순서

`lh3.googleusercontent.com/d/<id>=s1920`(긴 변 1920px로 리사이즈) → 실패 시 API가 준 썸네일 → 실패 시 API 원본 다운로드 순으로
시도하고, 마지막으로 성공한 방식을 다음 사진에도 우선 쓴다. 재생 시작 후 전체 사진을 백그라운드로 미리 받아 서비스 워커에 캐시한다.

## BD-0003 요구사항 대응

| 요구사항 | 구현 |
|---|---|
| FR-001 사진 업로드·슬라이드쇼 생성 | `public/js/editor.js`, `POST /api/slideshows`, `POST .../photos` |
| FR-002 전환·애니메이션 효과 | `public/js/effects.js` (페이드·크로스 디졸브·줌 인/아웃·팬·Ken Burns·블러 전환·패럴랙스, 자동/지정) |
| FR-003 비율 감지·레이아웃 | 화면 비율과 사진 비율 비교 → 비슷하면 꽉 채움, 다르면 확대·블러 배경 위에 원본 배치 (`layoutFor`) |
| FR-004 고유 URL | 추측하기 어려운 12자 ID → `/s/<id>` |
| FR-005 전체화면 무한 재생 | `public/js/player.js` (Web Animations API, 순환·프리로딩) |
| 비기능: 성능 | 업로드 전 축소, 다음 사진 프리로딩, 지난 슬라이드 DOM 제거, WebGL 미사용 |
| 비기능: 안정성 | `?lite=1` 저사양 모드(blur/parallax 대체), 서비스 워커로 오프라인 재생, 불러오기 실패 사진 건너뜀 |
| 비즈니스 규칙 4 (즉시 반영) | 재생기가 메타데이터를 10초마다 갱신하고 편집기가 미리보기에 즉시 갱신 신호 전달 |

예외 상황(사진 0장, 없는 URL, 비율 혼재, 네트워크 끊김)도 재생기에서 처리한다.

## BD-0003 "미결정 사항"에 대해 임시로 정한 것

문서에서 확정되지 않은 항목이라 아래처럼 가정했다. 바꾸고 싶으면 알려 달라.

| 미결정 항목 | 이번 구현의 가정 |
|---|---|
| MVP 범위 | FR-001~005만. 배경음악·문구 오버레이·드래그 순서 변경·노출 시간 설정·QR·테마 등은 제외 |
| 계정/인증 | **계정 없음.** 생성 시 발급되는 편집 키(URL 해시 `#key=`)를 가진 사람만 수정 가능. 키는 서버에 해시로만 저장 |
| URL 접근 권한 | 재생 URL은 공개(링크를 아는 사람 누구나). ID가 추측하기 어렵다는 점에만 의존 |
| 자동 효과 선택 기준 | 사진 순서대로 효과를 순환. 세로 사진에는 좌우 팬 이동을 쓰지 않음 |
| 업로드 제한 | 슬라이드쇼당 100장, 사진당 12MB(서버 상한) |
| 삭제 정책 | 편집 화면의 "슬라이드쇼 삭제"로 사진·설정 즉시 영구 삭제. 자동 보관 기간 만료는 없음 |
| 오프라인 | 한 번 재생한 뒤에는 서비스 워커 캐시로 재생. 처음부터 오프라인인 환경용 로컬 패키지는 미구현 |
| 저장소 | 로컬 파일 시스템(S3/CDN 미사용) |
| 재생 타이밍 | 사진당 정지 5초 + 전환 1.6초 (`player.js` 상단 상수) |

## 알려 둔 한계

- 자동재생 정책상 **전체화면은 사용자 클릭/키 입력이 필요**하다(브라우저 제약).
- 서비스 워커는 HTTPS 또는 `localhost`에서만 동작한다. 현장 PC에서 IP로 http 접속하면(서버 모드) 오프라인 캐시가 적용되지 않는다. GitHub Pages(HTTPS)는 해당 없음.
- 오프라인 재생을 믿으려면 **예식 전에 현장 PC에서 재생 URL을 한 번 열어 두자**(사진 수 × 0.2초쯤 걸려 전체가 캐시된다).
- 드라이브 모드: 폴더 링크를 아는 사람은 누구나 사진을 볼 수 있다. 사진 **내용만 교체**(같은 파일에 새 버전 업로드)하면 서비스 워커 캐시 때문에 이미 열어 본 브라우저에는 옛 사진이 남을 수 있으니, 교체 대신 새 파일로 올리자.
- 드라이브 모드: 이미지 경로(`lh3.googleusercontent.com`)는 구글이 공식 문서로 약속한 주소 형태가 아니다. 막히면 자동으로 API 썸네일/원본 다운로드로 넘어가지만, 원본 다운로드는 용량이 커서 느릴 수 있다. Drive API 호출은 갱신 주기(30초)와 무료 한도를 고려한 값이다.
- 재생 URL 자체는 로그인 없이 열리므로, 링크가 유출되면 사진이 노출된다.
- HEIC 등 브라우저가 해석하지 못하는 형식은 업로드 시 오류로 표시된다(JPEG/PNG/WebP 사용).
- 서버 1대·파일 저장 구조라 다수 서버로 확장하려면 저장소 교체가 필요하다.

## 구조

```
server.js                서버 모드: API + 정적 파일 서버 (Node 내장 모듈만 사용)
public/                  서버 모드 화면 + 두 모드가 공유하는 코드
  js/effects.js            효과 정의·레이아웃 판정
  js/player-core.js        재생 코어 (사진 소스만 바꿔 끼우면 동작)
  js/player.js             서버 모드 소스 (/api)
  js/drive-source.js       드라이브 모드 소스 (파일명 규칙, Drive API)
pages/                   Pages 모드 전용 화면·서비스 워커·설정(config.js)
scripts/build-pages.mjs  pages/ + 공유 코드 → dist/ (배포 산출물)
.github/workflows/       Pages 자동 배포
test/                    API·효과·드라이브 소스 테스트 (npm test)
```
